# local-eval-lab

Companion code for **Mastering RAGAS & DeepEval: A Practical Hands-On Guide to LLM
Evaluation with Local Ollama Models** (AI Engineering Insider).

A complete Local LLM Evaluation Platform: a RAG assistant for a fictional cloud
storage company (Helios), a 30-item golden dataset, RAGAS and DeepEval metrics judged
by local Ollama models, custom metrics, a three-judge comparison against 40 human
labels, bias probes, a multimodal experiment with Qwen2.5-VL, a regression gate, a
FastAPI backend, a Streamlit dashboard, and GitHub Actions CI. No paid API is used.

## Requirements

| Component | Version tested |
|---|---|
| Python | 3.12 (3.10+ supported) |
| Ollama | current release from ollama.com |
| ragas / deepeval | 0.4.4 / 4.3.4 |
| chromadb / ollama (Python) | 1.5.9 / 0.6.3 |
| RAM | 8 GB minimum, 16 GB comfortable |

Models: `qwen2.5:3b`, `qwen2.5vl:3b`, `qwen3:1.7b`, `llama3.2:1b`, `nomic-embed-text`.

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
make models            # ollama pull for all five models
make check             # 01_check_env.py: packages, server, models, smoke test
make ingest            # chunk + embed + store in ChromaDB
make ask Q="How long are soft-deleted objects kept on Business?"
make test              # offline unit tests (no Ollama needed)
```

## The evaluation workflow

```bash
make golden    # validate golden set, run the RAG system once, freeze responses to JSONL
make ragas     # RAGAS metrics on the frozen responses (judge: qwen2.5:3b)
make deepeval  # DeepEval metrics + GEval + custom metric on the same responses
make judges    # qwen2.5:3b vs qwen3:1.7b vs llama3.2:1b against 40 human labels
make bias      # position, verbosity, prompt-sensitivity, self-preference probes
make mm        # multimodal evaluation with qwen2.5vl:3b
make full      # end-to-end run stored in SQLite (used by API, dashboard, CI)
make test-eval # DeepEval pytest suite: deepeval test run tests/eval/test_rag_quality.py
```

Regression gate:

```bash
python scripts/10_regression_gate.py --candidate results/run_<id>.jsonl --update-baseline  # adopt
python scripts/10_regression_gate.py --candidate results/run_<id>.jsonl                    # gate
```

## Platform

```bash
make api    # http://localhost:8000/docs   (/ask, /evaluate, /jobs/{id}, /runs, /human-labels)
make dash   # http://localhost:8501        (overview, run detail, judges, human labeling, ask)
```

## Honest limits

* Scores from 1B to 3B judges are noisy estimates, not ground truth. Validate every
  judge against human labels (`make judges`) before trusting it in a gate.
* The human labels in `calibration_v1.jsonl` were written for teaching. Relabel a
  sample yourself, and build a calibration set from your own system's outputs.
* CPU inference is slow: a full RAGAS run on 30 items with seven metrics takes tens of
  minutes on a laptop. Use `--limit` and `--metrics` while iterating.
